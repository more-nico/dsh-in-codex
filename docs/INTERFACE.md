# 面板信息规划

面板用于查看由 Codex 主会话调度的 DSH 子任务，不是第二个聊天输入窗口。

## 宿主入口

- 菜单入口、面板页面标题统一显示为 **DSH in Codex**。
- MCP 服务通过 `serverInfo.icons` 提供内嵌 SVG 小图标，聊天入口可使用服务图标作为回退；
  页面 favicon 使用同一资产，构建后的 CLI 和面板均不需要额外请求图标文件。
- 当前桌面客户端会将 MCP 入口统一归入新标签页的“更多工具 → 插件和 MCP”。
  上方工具区由客户端内置工具占用，插件没有可声明的固定或排序选项。

## 信息层级

1. **顶栏**：组合 SVG Logo、右上角子对话切换入口和始终显示的设置入口；子对话切换按钮与设置按钮使用统一高度。
2. **任务概览**：任务名称、一个生命周期状态标签；有模型信息时显示静态文字。
3. **主要内容**：已完成任务首先呈现最终 Markdown 总结；执行过程默认收起。
4. **次要信息**：过程中的工具调用、输入指令、用量只在展开过程后查看。
5. **页脚**：主会话调度说明和待接收结果数量，不占据正文的主要位置。

## 设置页

- 顶栏齿轮设置按钮始终显示；打开设置页时保持按下态，再次点击关闭设置页并回到任务视图。设置页不提供“返回任务”按钮，关闭统一通过该齿轮开关完成。
- 设置页首次打开才挂载，关闭后以 `hidden` + `inert` 保留挂载；未保存草稿和上次保存结果在齿轮开合之间保留，关闭不会清空编辑。
- 设置是插件级全局配置，所有聊天共用。面板通过仅 app 可见的 `dsh_settings` 读取和保存；主会话模型不能调用该工具。普通 `dsh_models` 返回 `{presets,settings,effective,all_models}`：`presets` 是两个已配置档位，`all_models` 每项包含 `provider`、`id`、`name`、`contextWindow`、`input`、`reasoningEfforts`，来自 DSH 解析后的模型信息；无法获取的元数据为 `null`，不会猜测。不返回临时探测进程的 `selected`。传入 `model: {provider,id}` 时，`probe.thinkingLevels` 返回该模型支持的思考档位。
- `dsh_models` 传入 `agentId` 时，`agent_model_source` 区分运行进程的 `live-dsh` 和任务记录的 `stored-task-state`；后者可能只是排队任务的预期模型。`doctor` 的 `bridge.probe_model` 也是临时进程的模型，不代表插件档位。派发显式模型和思考档位前会核对 DSH 实际采用的值。
- 插件保留全局面板入口，DSH 任务按项目显式开启。新项目无配置时默认禁用；主会话说“为当前项目启用 dsh in codex”可通过本地 CLI 开启。后端检查主会话绑定项目，未开启时不接受任务、模型探测或历史读取。更新插件后需重载 Codex。
- 插件不提供独立的默认模型或默认思考强度。常规模型（`slot1`，一般任务）与增强模型（`slot2`，复杂任务/更深推理）各自保存 provider/id/thinking，两个档位独立，可指向同一模型并使用相同或不同思考档位（例如常规 high、增强 max），也可完全相同。主 Agent 先调用 `dsh_models` 发现已配置档位，再按任务明确选档；插件不按任务文本自动路由，不按 Fast 等名称推断强弱，也不自动升档。
- 派发优先级为：显式 `model` > 所选且非空的 `preset` > DSH 原生配置。只有 `dsh_spawn` 显式传 `preset: "slot1" | "slot2"` 时使用对应档位；显式 `model` 始终优先，档位留空则沿用 DSH 原生配置，不构成第三套默认。仅传 `name`/`task`、不带 `preset` 的旧调用保持底层兼容。
- 兼容与迁移：`preset` 仍为 `"slot1"` / `"slot2"`，已有 `settings.json` 继续有效。旧版 `defaultModel` 只在加载时用于填充空档位，已有档位保留；重写后的文件仅含新形状，不再写入第三个默认。
- 并发限制：全局最大并发与每聊天最大并发均可在面板调整，范围 1–32；出厂默认全局 10、每聊天 5，仅在尚无已保存设置且无环境变量覆盖时生效，每聊天上限仍受全局上限约束。已有显式保存值优先，升级不会强制改成 10/5。保存后作用于后续调度；提高上限可启动排队任务，降低上限不终止正在运行的任务。
- 保存模型选择前按专用 profile 校验模型可用性和思考档位；失败时不覆盖上次保存的设置，并保留未保存的编辑以便重试。保存只影响之后的派发，运行中任务的模型不变。
- 设置页通过仅 app 可见的 `dsh_model_migration` 列出本机 DSH profile、预览 provider 和模型，并迁移勾选项。目标同名 provider 只追加新模型，已有同 ID 模型显示“已配置”且不可选择；写入前备份专用 profile，不改来源 profile 或模型档位。
- 设置保存在插件数据目录（`DSH_IN_CODEX_DATA_DIR`）的 `settings.json`，不写入 DSH / web profile 或仓库；保存的 `settings` 对象仅含 `presets.slot1`、`presets.slot2`、`maxConcurrent`、`maxPerThread`，不含凭据。并发环境变量只作为首次运行的默认值。
- 任务视图仍然只读；设置页是面板唯一的配置表单，不用于发送聊天指令、停止任务或回答交互。

## 时间与导航

- 首次打开优先显示正在运行的任务，再考虑等待交互、启动中和排队任务；同类取最近的一次运行。
  全部结束时显示最近结束的结果。面板已打开后，新任务与追加消息只更新列表，不改变当前选择。
- 派活/发消息的工具返回 `panel.shouldOpen`：为 true 时主会话调用一次 `dsh_panel`，一批任务只开一次；
  已打开或正在打开时不再调用。仅 `dsh_panel` 关联 UI 资源，数据工具不重复渲染面板。
- `dsh_poll` 携带当前面板实例 ID，用可取消的长轮询记录会话内的在线状态；轮询取消时释放实例，
  异常断线后的记录最多保留 45 秒。打开请求 10 秒未连接可重试。宿主仍需支持 MCP Apps 面板。
- 当前任务的耗时只出现一次：已完成时位于“用时 ×分×秒 ›”折叠行，其他状态位于进度行。
- 任务列表仅显示名称与活动状态，不重复耗时、token 或调用数。
- 任务列表是右上角悬浮层，默认折叠，不改变正文布局。未固定时选择任务、点击外部自动收起。
- 列表标题区可切换“固定悬浮”；固定后选择任务、点击正文仍保持展开。点击折叠控制或按 Escape
  可随时收起，重新展开时保留固定选择，右上角入口以图钉标识固定状态。
- 成功和失败任务都放入默认折叠的“已完成”分组；失败任务保留失败标记和错误信息。
  切回成功完成的任务时重新以总结视图打开。

## 过程与交互

- 点击用时行展开过程，箭头旋转、内容高度与透明度轻微过渡（约 200ms）。
- 总结始终留在过程下方，展开时不重复最终回复；隐藏的过程不能获得焦点。
- 遵守系统的减少动态效果设置；命令和工具输出在过程内进一步折叠。
- 同一次工具调用的参数与返回结果合并为一条折叠记录，按运行 ID 与调用 ID 配对；
  展开后分别查看参数和结果。调用尚未加载到当前消息页时，结果独立保留，加载历史后合并。
- 工具卡片以“运行测试”“修改文件”“读取文件”“搜索代码”等动作作为标题，原始工具名放次要位置；显示执行中、成功、失败、中断或部分结果。命令摘要提取测试数、构建结果、耗时和退出状态；文件修改显示路径、增删行数及有限长度的差异预览；搜索结果按文件与行号组织。原始参数和完整输出留在折叠详情，长输出继续分页。
- 默认最近 50 条，主动查找历史才分页追加，保持阅读位置。
- 任务视图无输入框、发送、停止或确认表单；等待交互时只提示“等待主会话处理”。
- 指令、停止、交互回答与结果确认通过 Codex 主会话工具完成；设置页是唯一的配置表单，见“设置页”。

## 性能与长文本（源码更新，尚未发布）

- 自动刷新按聊天合并到最多约每秒 4 次；没有可见变化的思考/工具参数片段不触发重复刷新。
  主会话的等待、完成和交互通知独立处理，不使用面板的刷新限速。
- 面板使用 `transportVersion: 2`，传输消息窗口的 ID 和变化的消息；缓存缺失或守护重启后
  重新获取完整窗口。未带版本参数的旧面板仍使用原有格式。
- 消息和最终总结自动预览最多 8,000 个字符；主动阅读时每段最多 16,000 个字符。
  记录原文完整保留。历史分页仍为 50 条，工具折叠行显示预览字符数与总字符数。
- 折叠的工具详情和已完成任务的过程不挂载正文；收起后释放正文。静态消息复用渲染结果，
  app-only 轮询只返回结构化数据，避免额外复制一份 JSON 文本。
- 切换任务时释放上一个任务的已加载历史，后台任务仅保留最近窗口；已离开页面的历史请求
  返回后丢弃，避免重新填充不再阅读的内容。
